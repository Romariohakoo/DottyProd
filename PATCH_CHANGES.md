## 3. Добавлены backup и инструкции восстановления

Новый `deploy/backup.sh` запускается **до замены конфигурации и образов**. Он сохраняет:

- текущие Compose, `.env`, `frontend.env` и конфигурацию прокси/мониторинга;
- точные имена образов работающих frontend/backend;
- дамп PostgreSQL в формате `pg_dump -Fc`.

Каталог backup создаётся с ограниченными правами через `umask 077`. Дамп сначала записывается как `.partial`; после проверки `pg_restore --list` переименовывается в `database.dump`. Ошибка backup останавливает деплой. При первом развёртывании без предыдущих Compose и `.env` резервирование пропускается.

В [deploy/OPERATIONS.md](deploy/OPERATIONS.md) описаны диагностика, откат приложения, пробное восстановление в отдельную БД и восстановление production. Отдельно разобран случай, когда старый образ не знает новой Alembic revision.

Автоматического отката БД нет: он мог бы уничтожить записи, появившиеся после создания дампа. Внешнее хранение резервных копий и резервирование S3 этим патчем не настраиваются.

## 6. Ошибка публикации образа больше не считается успехом

Из команды Kaniko удалён безусловный `|| true`. Ошибки сборки и публикации, включая `MANIFEST_FOR_TAG_EXISTS`, теперь возвращают ненулевой код и останавливают pipeline.

Тег образа изменён с `<commit>` на `<commit>-<pipeline-id>`, чтобы разные pipeline одного коммита не публиковались в один тег. Повтор конкретного build job внутри того же pipeline всё ещё может столкнуться с занятым тегом; такая ошибка не скрывается.

Для backend-тестов также восстановлен JUnit-отчёт, публикуемый через CI artifacts даже при падении тестов.

Файл: [.gitlab-ci.yml](.gitlab-ci.yml).

## 7. Повторы создания защищены идентификатором операции

В DTO создания поездки, места и события добавлено необязательное поле `clientRequestId`. Существующий API-клиент преобразует его в backend-поле `client_request_id`.

Mutation hooks создают UUID и сохраняют его в `useRef`. Повтор неизменённого запроса после ошибки использует тот же UUID. Изменение данных или успешное завершение операции позволяет создать новый ключ; явно переданный клиентом идентификатор сохраняется. Для мест и событий ключ также учитывает поездку.

На backend создание поездки с идентификатором операции блокирует строку владельца перед поиском существующей записи. Поэтому два конкурентных одинаковых запроса возвращают одну поездку, а не конкурируют при вставке.

Защита расширена на новые функции проекта:

- **Галерея:** повтор загрузки того же объекта `File` в то же событие использует прежний UUID до успеха; разные поездки/события имеют отдельные ключи.
- **Форма билета:** событие и фото получают отдельные стабильные ключи. Если событие уже создано, а загрузка фото завершилась ошибкой, повтор с теми же данными не создаёт второе событие.
- **Ошибка фото:** удалено подавление ошибки через `.catch(() => undefined)`. Пользователь видит ошибку и может повторить отправку; данные поездки перечитываются после попытки.

Ключи хранятся в памяти открытой формы. Перезагрузка страницы, закрытие формы или новый выбор файла не обеспечивают сохранения прежнего ключа.

Основные файлы: [travelhub.dto.ts](frontend/src/shared/api/travelhub.dto.ts), mutation hooks в `features/trip/create`, `features/place/create`, `features/event/create`, [модель загрузки вложений](frontend/src/features/attachment/manage/model/index.ts), [API вложений](frontend/src/features/attachment/manage/api/index.ts), [CreateFromTicketForm.tsx](frontend/src/features/event/from-ticket/ui/CreateFromTicketForm.tsx), [trip_repository.py](backend/src/repositories/trip_repository.py), [trip_service.py](backend/src/services/trip_service.py).

## 8. API запрещает сокращать поездку за пределы событий

При изменении поездки backend блокирует её строку и перечитывает актуальные границы. Если новый интервал сокращается, проверяются начало и конец всех существующих событий. Если хотя бы одно выходит за новые даты, API возвращает HTTP 422 с причиной `Event dates must be within the trip dates`; изменение не сохраняется.

Сокращение пустой поездки и сокращение с сохранением всех событий внутри границ разрешены. Проверка находится на backend и применяется также к прямым запросам API.

Файл: [trip_service.py](backend/src/services/trip_service.py). Общая проблема согласования часовых поясов этим изменением не решена.

## 9. При смене сессии очищается кеш

При выходе и успешном входе отменяются текущие React Query queries и очищается весь QueryClient cache. При выходе также удаляется локальный access token и сбрасываются данные текущего пользователя.

Переход выполняется через `window.location.replace`: после входа на `/`, после выхода на `/login`. Полная загрузка страницы пересоздаёт активные наблюдатели запросов и исключает показ старых данных из прежнего дерева приложения.

Файлы: [use-login-mutation.ts](frontend/src/features/user/login/model/use-login-mutation.ts), [use-logout-mutation.ts](frontend/src/features/user/logout/model/use-logout-mutation.ts).
