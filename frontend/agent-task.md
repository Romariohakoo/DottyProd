# Дополнение к `AGENTS.md`: режим небольших хотфиксов

Этот файл дополняет `AGENTS.md`, но не заменяет его. Конкретную проблему и желаемый результат пользователь описывает в текущем сообщении. Не переноси в задачу требования из прошлых сообщений, если пользователь явно их не повторил.

Используй этот режим, когда запрос описывает небольшую локальную UI-ошибку или очевидную правку существующего поведения: лишний текст, дублирующий заголовок, неверную подпись, локальный стиль, неработающую кнопку с понятной причиной и подобные случаи.

## Как выполнять хотфикс

1. Сначала проверь `git status --short` и сохрани все существующие изменения пользователя.
2. Найди точное место проблемы по тексту, компоненту или наблюдаемому поведению. Для текста сначала используй точный поиск через `rg`.
3. Определи ближайший существующий аналог и кратко назови его перед изменением.
4. Если причина очевидна и исправление локальное, внеси минимальную правку сразу. Не останавливайся ради согласования деталей, которые уже однозначно заданы пользователем.
5. Если найдено несколько источников проблемы или исправление требует нового паттерна, изменения типов, контракта, shared-компонента, конфигурации либо нескольких независимых решений, остановись и следуй правилам согласования из `AGENTS.md`.

## Границы исправления

- Исправляй причину, указанную пользователем, а не соседние недостатки интерфейса.
- Не рефактори компонент и не меняй его структуру, если достаточно удалить или заменить один элемент.
- Не переименовывай сущности, не меняй типы, запросы, состояние, роутинг и публичные API ради визуального хотфикса.
- Не исправляй попутно предупреждения линтера и чужие изменения, если они не вызваны правкой.
- Не добавляй зависимости, абстракции, новые базовые компоненты и стили «на будущее».
- Если пользователь просит убрать видимый дубль, удаляй только дублирующий видимый элемент. Сохраняй полезную семантику и accessibility-атрибуты (`aria-label`, роли, связь с заголовком), если они сами не являются причиной проблемы.
- Не меняй данные или поведение вложенного компонента, когда проблема находится только в его обёртке.

Пример: если во вкладке уже есть основной заголовок «Места», а вложенный виджет повторяет «Места на карте», нужно удалить только повторный видимый заголовок виджета. Саму карту, empty state и доступное имя секции менять не нужно.

## Проверка и отчёт

После изменения:

1. Просмотри diff только затронутого файла и убедись, что он содержит ожидаемую локальную правку.
2. Выполни `git diff --check`.
3. Выполни `pnpm check`, если это кодовая правка. Учти, что команда запускает автофикс и генерацию типов.
4. После проверки снова просмотри `git status --short`. Если проверка изменила посторонний файл, восстанови его состояние, которое было до запуска команды, не затрагивая пользовательские изменения.
5. В итоговом сообщении кратко укажи: что исправлено, какой файл или аналог использован и какие проверки действительно прошли. Отдельно сообщи о существующих предупреждениях, не выдавая их за ошибки хотфикса.

Для такого локального хотфикса не запускай браузер, dev-сервер или production build без необходимости, следующей из характера изменения или явного запроса пользователя.
