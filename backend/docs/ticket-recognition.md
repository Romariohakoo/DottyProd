# Распознавание билета

В `backend/.env` добавьте `OPENROUTER_API_KEY` и при необходимости
`TICKET_MODEL=z-ai/glm-4.6v`. Запускайте backend из каталога `backend`, чтобы
настройки прочитали этот `.env`. Ключ не передаётся фронтенду.

POST `/api/trips/{trip_id}/tickets/recognize`: multipart-поле `file`, JPEG/PNG.
Нужна авторизация и право редактирования поездки. Проверить можно через
`/api/docs`. Ответ — плоский черновик с `transport_type`: `plane`, `train`,
`bus` или `other`. Помимо `transport_type` и `review_required`, в нём есть
только поля выбранного типа.

| Тип | Поля |
| --- | --- |
| `plane` | `from_airport`, `to_airport`, `date`, `departure_time`, `arrival_time`, `seat`, `flight_number` |
| `train` | `from_station`, `to_station`, `date`, `departure_time`, `arrival_time`, `platform_number`, `carriage_number`, `seat_number` |
| `bus` | `from_name`, `to_name`, `bus_number`, `departure_time`, `arrival_time` |
| `other` | `other_fields`: массив `{ "name": "...", "value": "..." }` |

Дата — `YYYY-MM-DD`, время — `HH:MM` как напечатано на билете. `null` у
поля выбранного типа означает неизвестное значение. Если изображение не является
одним билетом, распознавание завершается ошибкой. Пользователь должен подтвердить
результат до создания события.

Backend передаёт оригинал изображения OpenRouter одним запросом (таймаут 60 секунд,
до 4096 выходных токенов, включая обязательное рассуждение модели).
Автоматических повторов нет.
Используется существующий httpx, новых зависимостей нет. Изображения и ответы
не сохраняются сервисом распознавания и не записываются им в логи.

Запрашивается json_schema со strict=true и require_parameters=true; дополнительно
ответ проверяется Pydantic. Поддержка строгой схемы зависит от провайдера GLM:
наличие response_format в каталоге не гарантирует строгое соблюдение схемы.
Если провайдер не поддерживает запрос или ответ некорректен, API возвращает 502,
без переключения на свободный текст. Отсутствующий ключ даёт 503.

Без ключа проверены только подменённые ответы. Реальную совместимость GLM с
этой схемой, качество чтения билетов и стоимость нужно проверить после настройки
ключа. Оптимизация разрешения изображения — этап 5.
